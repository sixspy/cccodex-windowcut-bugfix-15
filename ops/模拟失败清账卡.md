# 模拟失败清账卡（BUGFIX-15）

> 本卡为模拟物化失败（`fail_simulate=true`）清账口径的唯一裁决文件。
> 择定后当日禁止改口；代码实现必须与本卡一致，禁止甲乙混用。

## 卡面

| 项 | 内容 |
|----|------|
| 缺陷编号 | BUGFIX-15 |
| 缺陷现象 | 打开 fail_simulate 后接口报 500，materializations 台账却已插入并提交「成功」物化行，半截污染结账 |
| 择定路径 | **乙路径：只保留失败票，并在同一事务内抹掉成功行；失败票写入或抹除任一步失败，则票与抹除整体回滚** |
| 否决路径 | 甲路径（同事务删除成功行并回滚至台账零增，不留失败票） |
| 择定日期 | 2026-11-21 |
| 冻结规则 | 2026-11-21 当日禁止改口；后续如需改口径须另立新卡，不得覆盖本卡 |
| 代码锚点 | `backend/clearing_card.py` 的 `CLEARING_CARD.path == "乙"`，与本卡同源 |

## 乙路径不变量（禁止偏离）

1. 模拟失败触发时，接口仍返回 500（报错语义不变，禁止只改报错文案充当修复）。
2. 该次请求在 `materializations` 台账中**零成功行净增**：先插的成功行必须在同一事务内 DELETE 抹除。
3. 同事务写入且仅写入一张失败票（`failure_tickets`），失败票是该次物化唯一留存凭证。
4. 抹除成功行、写失败票、写审计任一步失败 → 整体回滚至事务保存点：成功行不留、失败票不留、审计不留。
5. 禁止甲乙混用：不得出现「回滚到零增且不留票」的甲路径分支，也不得保留成功行。
6. 偏离本卡的写请求一律拒写，并在 `clearing_deviation` 记「清账偏了」。

## 五处同态口径

| 同态面 | 模拟失败后应呈现 | 争用被拒后应呈现 |
|--------|------------------|------------------|
| 台账 materializations | 零成功行净增（成功行已同事务抹除） | 零行写入（后到者不写业务） |
| 失败票 failure_tickets | 恰好 1 张失败票，分区/行/金额与被抹成功行同源 | 0 张（未进入业务写阶段） |
| 结账灯 reconcile | 不以被抹行充当对齐素材；`tolerate_orphan_mat` 取消；带失败票数 | aligned 不被污染，失败票数不变 |
| 审计 audit_trail | 记 materialize_fail_sim，payload 含失败票 id 与分区 | 争用只记 contention_log，不产生物化审计 |
| 争用 contention_log | 0 条（正常持锁不记争用） | 恰好 1 条「争用」，锁键 materialize:{wid} |

## 并发口径

两人同时对同窗发起一真一假物化，必须争抢同一把物化锁 `materialize:{wid}`：
先到者持锁完成（真→成功行，假→乙路径清账）；后到者拿锁失败，仅记争用并返回 409，不写任何业务数据。
